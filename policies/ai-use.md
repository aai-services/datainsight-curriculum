# AI-Use Policy

Status: draft for review.

AI tools are part of how data work is done now, and this program teaches you to use them well. The goal is that you can do the work, judge the work, and take responsibility for it, with or without AI.

## Principles

1. **You are responsible for everything you submit.** If an AI tool made a mistake and you submitted it, it is your mistake.
2. **Understand every line.** You must be able to explain any code, number, or claim in your work. The program lead or your peer reviewers may ask you to walk through it.
3. **Disclose your use.** From Stage 2 onward, every project includes an AI-use log.
4. **Verify, do not trust.** Check AI output the same way you would check a colleague's work: run it, test it, and compare it with what you expect.
5. **Protect data and secrets.** Never paste personal data, confidential data, passwords, or access keys into an AI tool.

## What is allowed at each stage

| Stage | Allowed | Not allowed in graded work |
|---|---|---|
| Core Stages 0 and 1 | Asking an AI tool to explain concepts, error messages, or documentation; asking for hints; asking it to quiz you | AI-written code or text |
| Core Stage 2 | All of the above, plus AI-written code and drafts, recorded in the AI-use log | Submitting AI output you have not checked and cannot explain |
| Core Stage 3 and Advanced | AI tools as a full part of your workflow, recorded in the AI-use log | Submitting AI output you have not checked and cannot explain |

Stages 0 and 1 are tutor-only for a reason: you need your own working knowledge first, or you will not be able to spot AI mistakes later.

## The AI-use log

Add a file named `AI_LOG.md` to each project repository from Stage 2 onward. For each substantial use, record:

- **What I asked**: a short description or the prompt
- **What I used**: which part of the output ended up in the project
- **What I changed or rejected, and why**
- **How I checked it**

A short, honest log is better than a long one. Using AI heavily is fine when it is logged and checked.

## Using AI as a tutor

These prompts ask the tool to teach rather than to answer. Each module includes more.

- "Explain what this error message means, but do not fix my code. Ask me a question that helps me find the problem."
- "I think [concept] means [your explanation]. What is wrong or missing in my explanation?"
- "Give me three short practice questions on [topic], one at a time, and wait for my answer before giving feedback."

## Academic integrity

The following count as misconduct:

- Submitting AI-written code or text in Stages 0 and 1
- Leaving AI use out of the log
- Submitting work you cannot explain when asked
- Presenting another person's work as your own

First concerns are handled as a conversation with the program lead and a chance to redo the work. Repeated misconduct can lead to removal from the program.
