## 2. Why Git and GitHub (about 1 hour)

Git records every version of your work, so you can see what changed, when, and why, and undo mistakes. GitHub stores your Git projects online, so others can review them and you can build a public portfolio.

Four words you will use every week:

| Word | Meaning |
|---|---|
| Repository (repo) | A project folder whose history Git tracks |
| Commit | A saved snapshot of your changes, with a short message saying what changed |
| Branch | A separate line of work, so you can change things without touching the main version |
| Pull request | A request to merge a branch into the main version; this is where review happens |

Read GitHub's short guide *Hello World* (search "GitHub Hello World guide") and follow its steps in a practice repository of your own.

## 3. Markdown (about 30 minutes)

Markdown is plain text with a few symbols for formatting. You will use it for every README and every notebook text cell.

```markdown
# A heading
## A smaller heading

Plain text. **Bold**, *italic*, and a [link](https://example.org).

- A bullet
- Another bullet
```

## 5. Keeping secrets and personal data out (about 30 minutes)

Anything you push to GitHub may become public and stay in the history even after you delete it. Never commit:

- Passwords or access keys (API keys, tokens)
- Personal data about other people: names, phone numbers, addresses, ID numbers
- Data you do not have permission to share

If you need a key in your code, read it from an environment variable or a Colab secret, never type it into the notebook. This rule also applies to AI tools: do not paste keys or personal data into them.
